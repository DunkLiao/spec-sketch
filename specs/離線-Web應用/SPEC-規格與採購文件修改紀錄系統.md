# 規格與採購文件修改紀錄系統 — 系統規劃書

**架構**：單一 HTML 檔（前端）+ IndexedDB（本機資料庫）+ Apache ECharts（圖表，已內嵌離線）
**版本**：v1.1.0 ／ **更新日**：2026-07-30

---

## 一、設計原則

| 原則 | 說明 |
|---|---|
| 零安裝、零伺服器 | 雙擊 HTML 即可用，不需 IIS／Node／資料庫主機，免資訊處開機器 |
| 完全離線 | ECharts 已內嵌於檔案內（1 MB），**不連外網**，符合行內封閉網段限制 |
| 資料不出本機 | 全部資料存於瀏覽器 IndexedDB，無任何雲端傳輸 |
| 可交換 | CSV（UTF-8 BOM，Excel 直開不亂碼）+ JSON 全庫備份／還原 |
| 三層資料結構 | 專案 → 文件 → 修改紀錄，符合實務會辦流程 |
| 不混入假資料 | v1.1.0 起移除示範資料產生器，確保庫內僅有真實業務紀錄 |

---

## 二、資料模型（IndexedDB Schema）

資料庫 `SpecDocTrackerDB`（version 1），四個 Object Store：

### 1. `projects`（專案）
| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | string (PK) | 系統產生唯一碼 |
| `name` | string | 專案名稱 **（必填）** |
| `code` | string | 專案代號，如 PRJ-115-001 |
| `owner` | string | 主辦人／單位 |
| `startDate` / `dueDate` | date | 起始日／預計完成日 |
| `status` | enum | 規劃中／進行中／審查中／已完成／暫停 |
| `memo` | string | 備註 |

### 2. `documents`（文件）— index: `projectId`
| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | string (PK) | |
| `projectId` | string (FK) | 所屬專案，**一專案多文件** |
| `name` | string | 文件名稱 **（必填）** |
| `docNo` | string | 文件編號 |
| `type` | enum | 規格書／需求規格／採購文件／招標文件／投標須知／契約草案／價格清冊／評選須知／其他 |
| `version` | string | 版次，如 V2.1 |
| `owner` | string | 承辦人 |
| `pages` | number | 總頁數（供頁數欄位檢核參考） |

### 3. `records`（修改紀錄）— index: `docId`, `projectId`, `modified`, `proposeDate`

| 系統欄位 | 對應需求 | 型別 | 備註 |
|---|---|---|---|
| `proposedUnit` | **提出單位** | string | 必填，可從設定的單位清單下拉選取 |
| `proposer` | **提出人員** | string | |
| `proposeDate` | **提出日期** | date | 必填 |
| `modified` | **是否已修改** | `Y` / `N` | 表格中可一鍵切換 |
| `modifyDate` | **修改日期** | date | 選 Y 時自動帶今日；驗證不得早於提出日期 |
| `suggestion` | **修改建議** | text | 必填 |
| `pageRef` | **對應文件頁數** | string | 支援 `P.12`、`P.12-15`、`附件三 P.3` 等自由格式 |
| `memo` | **備註** | text | |
| `docId` / `projectId` | 關聯 | string | 自動由所選文件帶入 |

**衍生欄位（不儲存、即時計算）**
- 處理天數 = 修改日期 − 提出日期（已修改）／今日 − 提出日期（未修改）
- 狀態 = 已修改 ／ 待修改 ／ **逾期未修改**（未結且停留 > SLA 天數，預設 14 天可調）

### 4. `meta`（設定）
存放 SLA 逾期天數、提出單位選項清單。

## 三、功能模組

| 模組 | 功能 |
|---|---|
| **進度追蹤儀表板** | 7 張 KPI 卡 + 6 張 ECharts 圖 + 專案進度明細表（可下鑽） |
| **專案管理** | 新增／編輯／刪除（含連動刪除下層）、排序、即時完成率 |
| **文件管理** | 依專案／類型／關鍵字篩選、每份文件顯示建議數與完成率 |
| **修改紀錄** | 8 大欄位登錄、7 種條件複合篩選、欄位排序、分頁、**批次標記已修改**、Y/N 一鍵切換 |
| **匯入匯出** | 修改紀錄／文件／專案 CSV 匯出；CSV 匯入（自動建立不存在的專案與文件、支援民國年）；JSON 全庫備份還原 |
| **設定** | SLA 逾期天數、提出單位清單、清空資料 |

## 四、儀表板指標設計

**KPI 卡**：專案數 ｜ 文件份數 ｜ 修改建議總數 ｜ 已完成修改 ｜ 待修改 ｜ **逾期未修改** ｜ 平均處理天數

| # | 圖表 | 型別 | 管理意涵 |
|---|---|---|---|
| 1 | 各專案完成進度 | 水平堆疊長條（已修改／待修改／逾期） | 一眼看出哪個專案卡關 |
| 2 | 整體完成率 | 儀表 Gauge | 對上簡報的單一數字 |
| 3 | 每月提出 vs 完成趨勢 | 雙軸柱狀＋累計完成率折線 | 意見是否收斂、辦理是否跟得上 |
| 4 | 各提出單位案件量 | 堆疊柱狀（已／未修改） | 哪個單位意見最多、哪個單位案件最常積壓 |
| 5 | 未結案件停留天數分布 | Aging 柱狀（0-7／8-14／15-30／31-60／60+ 天） | 老化風險，60+ 天需專案列管 |
| 6 | 文件別建議數 Top 10 | 環圈圖 | 找出爭議最大的熱點文件 |

> 所有圖表隨「左側專案切換」即時重算，可單專案檢視或全行彙總。

## 六、部署與維運

1. **部署**：把 `規格與採購文件修改紀錄系統.html` 放在個人電腦或共用磁碟，以 **Chrome / Edge** 雙擊開啟即可。
2. **限制**：IndexedDB 綁定「瀏覽器 + 檔案路徑」，**換電腦或清瀏覽器資料會遺失**，且多人各自獨立、不同步。
3. **備份**：務必養成每週「全庫備份（JSON）」習慣，備份檔存到部門共用區。
4. **勿用無痕視窗**（IndexedDB 會被封鎖，系統會顯示提示訊息）。
5. **初次建檔**：建議先手動建立 1～2 筆紀錄後匯出 CSV，作為後續大量匯入的格式範本。
