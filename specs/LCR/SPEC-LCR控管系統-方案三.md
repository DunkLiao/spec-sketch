## 2. 背景與目的

因應 LCR LINE 小組指示，需定期（每月底）產出「月底 LCR 預估值」，並依結果決定是否呈報經理進行 LCR 評估。目前作業以人工通知、Excel 填報與人工催件方式進行，存在下列痛點：

- 資料提供狀態難以即時掌握，逾期需人工逐一催件。
- 資料基準日、來源單位、預估假設等檢核仰賴人工比對，易生疏漏。
- 缺漏／異常清單、歷史期別資料缺乏系統化留存與稽核軌跡。
- 跨期別重複作業，無法沉澱為標準化流程與可追溯紀錄。

本系統目標為將此控管流程**制度化、系統化、可稽核**，支援多單位、多期別長期營運，並與行內核心/風管系統勾稽。

---

## 3. 目標與非目標

### 3.1 目標
- 提供線上資料填報介面，取代人工 Email／Excel 交付。
- 自動化期限提醒與逾期告警，降低人工催件成本。
- 系統化檢核資料基準日、來源單位、預估標記與完整性。
- 建立缺漏／異常清單並自動回饋提供單位。
- 彙整為 LCR 月底預估值試算基礎資料，支援試算與決策呈報。
- 保留完整稽核軌跡與歷史期別資料，供事後查核與趨勢比對。

### 3.2 非目標（本系統不含）
- 月底實際 LCR 最終申報數之法定產製。
- LCR 計算方法或監理規範之變更維護。
- 未經確認之其他單位資料推估。
- 與外部監理機關系統之直接申報介接。

## 4. 使用者與角色權限

| 角色 | 對應單位 | 系統權限 |
|------|----------|----------|
| 資料提供者（財務部） | 財務部 | 填報「LCR 預估相關參考資訊」、查看自身提交狀態 |
| 資料提供者（風管部） | 風管部 | 填報「流動性覆蓋比率現金流入預估資訊」、查看自身提交狀態 |
| 資料彙整窗口 | LCR LINE 小組 | 發起期別任務、追蹤狀態、檢核、產生缺漏清單、彙整、匯出 |
| 系統管理者 | IT | 使用者/角色維護、期別參數維護、稽核軌跡查詢 |
| 經理（審閱者） | 管理層 | 檢視 LCR 預估結果與呈報依據（唯讀儀表板） |

> 權限採 RBAC（Role-Based Access Control），結合行內 AD / SSO 單一登入。

## 5. 系統架構與技術棧

### 5.1 整體架構
```
[使用者瀏覽器]
      │  HTTPS
┌─────▼───────────────────────────────────┐
│  前端 SPA (React / Vue)                   │
│  - 填報表單、狀態儀表板、檢核清單          │
└─────┬───────────────────────────────────┘
      │  REST / JSON API
┌─────▼───────────────────────────────────┐
│  後端 API (ASP.NET Core / Python FastAPI) │
│  - 業務邏輯、檢核引擎、權限、排程觸發      │
└─────┬───────────────┬─────────────────────┘
      │               │
┌─────▼─────┐   ┌─────▼─────────┐
│ 資料庫     │   │ 排程服務       │
│ SQL Server │   │ Quartz / Cron │
│ / Oracle   │   │ 期限提醒/告警  │
└───────────┘   └───────┬────────┘
                        │
                ┌───────▼────────┐
                │ 通知服務        │
                │ SMTP / Teams   │
                └────────────────┘
```

### 5.2 技術棧選型

| 層級 | 技術選項 | 選型理由 |
|------|----------|----------|
| 前端 | **React** 或 **Vue 3**（TypeScript） | 元件化開發、表單與儀表板互動性佳；若配合行內既有 .NET，可改採 ASP.NET MVC + Razor |
| UI 元件庫 | Ant Design / Element Plus | 內建表單驗證、表格、日期選擇，加速開發 |
| 後端 | **ASP.NET Core (C#)** 或 **Python FastAPI** | 與行內 .NET 技術棧一致；FastAPI 適合快速 API 與資料處理 |
| 資料庫 | **SQL Server** 或 **Oracle** | 與風管 BIS 系統技術一致，利於後續勾稽與 DBA 維運 |
| ORM | Entity Framework Core / SQLAlchemy | 減少手寫 SQL、支援 Migration |
| 排程 | Quartz.NET / APScheduler / Windows 排程 | 期限前提醒、逾期告警、每日狀態掃描 |
| 通知 | SMTP（Outlook/Exchange）+ Teams Webhook | 沿用行內郵件與 Teams 推播 |
| 報表/儀表板 | Power BI Embedded / SSRS | 資料到位率、逾期、異常視覺化 |
| 認證授權 | 行內 AD / LDAP + SSO（OIDC / SAML） | 單一登入、符合資安要求 |
| 檔案儲存 | SQL FileStream / 檔案伺服器 / SharePoint | 附件（預估明細檔）留存 |
| 部署 | IIS / Docker + 內部伺服器 | 依行內資安審查與既有環境 |

## 6. 資料模型（Data Model）

### 6.1 主要資料表

**T_PERIOD_TASK（期別任務）**

| 欄位 | 型別 | 說明 |
|------|------|------|

**T_DATA_SUBMISSION（資料提交）**

| 欄位 | 型別 | 說明 |
|------|------|------|
| SUB_ID | PK | 提交代碼 |
| TASK_ID | FK | 對應期別任務 |
| DEPT | VARCHAR | 提供單位（財務部/風管部） |
| DATA_NAME | VARCHAR | 資料名稱 |
| BASE_DATE | DATE | 提交資料標示之基準日 |
| IS_ESTIMATE | BIT | 是否為預估數 |
| ASSUMPTION | TEXT | 預估假設條件 |
| ATTACHMENT_PATH | VARCHAR | 附件路徑 |
| SUBMIT_STATUS | VARCHAR | 已提供/未提供/逾期 |
| SUBMITTED_AT | TIMESTAMP | 提交時間 |
| SUBMITTED_BY | VARCHAR | 提交人 |

**T_CHECK_RESULT（檢核結果／缺漏異常清單）**

| 欄位 | 型別 | 說明 |
|------|------|------|
| CHECK_ID | PK | 檢核代碼 |
| SUB_ID | FK | 對應提交 |
| CHECK_TYPE | VARCHAR | 基準日/來源單位/預估標記/完整性 |

## 7. 功能需求（Functional Requirements）

### FR-01 期別任務發起
資料彙整窗口可建立新期別任務，設定期別、資料基準日、提供期限、預計產出日，系統自動通知財務部與風管部。

### FR-02 線上資料填報
提供單位登入後填報指定資料，含：資料名稱、基準日、預估標記、假設條件、附件上傳。表單具即時必填與格式驗證。

### FR-03 提供狀態追蹤
儀表板即時顯示各單位提交狀態（已提供／未提供／逾期），支援依期別、單位篩選。

### FR-04 自動期限提醒與告警
- 期限前 N 小時自動提醒尚未提交單位。
- 逾期後自動告警並通知資料彙整窗口。
- 通知管道：Email + Teams。

### FR-05 資料檢核引擎
系統自動檢核：
- 基準日是否等於任務基準日（不符 → 異常）。
- 來源單位是否正確。
- 預估數是否已標示、假設條件是否填寫。
- 必填欄位與附件完整性。

### FR-06 缺漏／異常清單與回饋
自動彙整檢核未通過項目為清單，發送回饋通知予提供單位，並追蹤補正狀態。

### FR-07 試算基礎資料彙整與匯出
通過檢核之資料彙整為 LCR 月底預估值試算基礎資料，支援匯出 Excel / CSV，供試算與呈報使用。

### FR-08 歷史查詢與稽核軌跡
可查詢歷史期別資料、比對趨勢，並提供完整操作稽核軌跡。

## 8. 非功能需求（Non-Functional Requirements）

| 類別 | 需求 |
|------|------|
| 安全性 | AD/SSO 登入、RBAC 權限、傳輸 HTTPS、敏感資料加密、稽核軌跡 |
| 效能 | 一般操作回應 < 2 秒；儀表板載入 < 3 秒 |
| 可用性 | 上班時段可用率 ≥ 99%；支援排程重試 |
| 稽核合規 | 符合行內資安規範與資料保存政策，操作可追溯 |
| 可維護性 | 期別/單位/檢核規則參數化，免改程式即可調整 |
| 相容性 | 支援行內標準瀏覽器（Edge / Chrome） |
| 備援 | 資料庫定期備份、可還原至任一期別基準點 |

## 9. 作業流程（系統化後）

```
資料彙整窗口建立期別任務（設定基準日、期限、產出日）
   ↓
系統自動通知財務部、風管部（Email + Teams）
   ↓
各單位線上填報資料 + 上傳附件（含預估標記與假設）
   ↓
系統即時更新提交狀態儀表板
   ↓
期限前自動提醒 / 逾期自動告警
   ↓
檢核引擎自動檢核基準日、來源、預估標記、完整性
   ↓
產生缺漏／異常清單 → 自動回饋提供單位 → 追蹤補正
   ↓
通過檢核資料彙整為試算基礎資料 → 匯出
   ↓
支援 7/28 產出月底 LCR 預估值
   ↓
依結果判斷是否呈報經理（唯讀儀表板供審閱）
```

## 11. 風險與因應

| 風險 | 影響 | 因應方式 |
|------|------|----------|
| 自建系統開發週期長 | 無法支援近期 7/28 產出 | 短期先以 Excel/VBA 或 Power Platform 過渡，本系統為中長期制度化方案 |
| 資安審查未通過 | 無法上線 | 及早提送資安評估、採 AD/SSO 與加密機制 |
| 與 BIS/核心系統勾稽複雜 | 資料介接延遲 | 分階段介接，先人工匯入再自動化 |
| 使用單位採用意願低 | 仍走人工 | 提供教育訓練、簡化填報介面、主管推動 |
| 檢核規則變動 | 需頻繁改版 | 檢核規則參數化，由管理者維護 |
